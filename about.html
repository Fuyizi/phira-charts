来下谱面的#

一句话版本：按难度挑 → 停一下看手感 → 下载 → 丢进 Phira。

  • 找谱：顶部按难度分标签页。搜索框是打完字按回车才搜的； 右边还能按标签筛，按时间 / 曲名 / 难度等排序。
  • 先看手感：鼠标停在封面上，会自动播一小段（静音，移开就停）。 点封面进详情页。
  • 下载：卡片右上角的圆钮，或详情页里的下载按钮。 文件名形如 窗 IN Lv.12+ 芣 v1.0.pez，一眼能看出是哪一版。
  • 装进 Phira：下载 → 打开 Phira 的「谱面导入 / 本地谱面」→ 选中那个文件。 不显示就检查一下有没有下完整。
  • 看老版本：详情页下半部分有「版本历史」。旧版本页不放预览视频 —— 视频演示的是最新版的手感。
  • 深色模式：右上角太阳 / 月亮按钮。

手机上一样能用：直接点卡片下载，细节参数在标题下面。

给谱师（自己传谱）#

第一步：拿访问码

找站长要一个，形如 px-xxxxxxxx。一人一个，别互相转借 —— 上传的作品归属是跟访问码绑定的，转借会让作品挂到别人名下。

上传一份新谱

  1. 打开「上传工具」页
  2. 把访问码填进「访问码」那一栏，点「记住」
    存在你自己的浏览器里，以后自动带上。
  3. 把 .pez 拖进下面的框
  4. 核对接析结果，改掉不对的地方
  5. 先点「只预览（不提交）」检查一遍
  6. 没问题再点「上传这份谱面」

会上传三样东西：

  • 谱面本体 → charts/<作品id>/<难度>-<版本>.pez
  • 封面 → assets/covers/<作品id>.jpg
  • 数据条目 → data/charts.js 里的一条

约 40 秒后 GitHub Pages 自动重建，首页上就能看到了。

自动解析可能不准的地方

字段说明
难度 来自谱面包里 info.txt 的 Level: 一栏。 别人写的是 IN Lv.15（难度名 + 数值），但有的包只写 Level: 0 —— 这时解析不到就不填，不会替你猜，请在表单里手动选。
谱师名义 Charter: 是整行原文，不会按逗号拆开（团体名会被拆坏）。
实际谱师 真正动手的人，跟名义经常不是一回事，需要的时候手动填。

曲名里的 #、emoji 之类都会原样保留，不会被当成注释截断。

创作中心：管已经传上去的作品

打开「创作中心」，填访问码登录。列表里只有你自己的作品。

操作说明
编辑 改曲名 / 中文名 / 曲师 / 谱师名义 / 难度值 / 版本号 / 许可 / 简介
改名 换作品 ID，仓库里的文件会一起搬到新目录，不会留断链
删除 摘掉数据条目 + 删掉 .pez
公开 / 私密 一键切换。私密的作品在站点上完全看不到（首页、列表、详情页都进不去）

新上传的谱默认是公开的；想先藏着，上传后去创作中心点一下「设为私密」。

⚠️ 两条必须记住的事

① 改信息，永远不要重传 .pez。
谱面文件动辄十几 MB，而 Git 会把每一个版本的历史都留着 —— 每重传一次就往仓库里堆一份。所以：

  • 只改曲名 / 简介 / 预览视频 / 难度这种信息 → 去创作中心改，只动数据
  • 只有谱面本身变了（音符、判定线、时长……）→ 才传新版本，并且改一下版本号

② 「删除」是留痕的。
文件从最新版里消失了，但它仍然躺在 Git 历史里，翻提交记录还是能下到。 所以对「绝对不想给别人看到」的谱，请先设成私密，别指望删除。

版本怎么管

同一份谱的多个版本：作品 ID 不变、难度不变，只改「版本号」。

  • 首页每组只显示最新的一版
  • 详情页的「版本历史」里能看到全部，也能翻回旧版
  • 下载下来的文件名带着版本号，不会互相覆盖

遇到问题

上传时会有一行行日志，出错基本都能一眼定位：

看到什么意思
访问码不对 其实是好消息 —— 说明链路已经通了，只是码打错了
Failed to fetch 网络到不了后端。换个网络试试，或者找站长
token 无效或已过期 重新登录一次创作中心即可

实在搞不定就把日志整段发给站长。

下面是站长自己的维护文档 —— 只有当你要改站点内容、自己排版、或者重新部署时才需要往下看。

这是什么#

一个纯静态的个人作品站，用来展示和分发自制谱面（.pez 格式）。 整个站没有任何后端，所有内容由 data/charts.js 这一个文件驱动， 直接双击 index.html 就能打开，传到 GitHub Pages 上也不需要任何构建步骤。

设计上分两种语气：首页借用投稿页的观感 —— 左侧导航、难度标签页、 一屏铺开的缩略图小卡片，每张卡片下面只放最必要的曲目信息 （曲名、曲师 / 谱师、难度、体积、短预览入口）； 详情页则回到维基百科式的展开 —— 目录、右侧信息框、 细线分隔的数据表、更新日志，适合慢慢读。 两套视觉效果共享同一套设计变量，改一处两边都会跟着变。

怎么加一份新作品#

推荐做法：打开上传工具，把 .pez 拖进去， 它会自动读出曲名、曲师、谱师、难度、音符数、判定线数量，并生成一段现成的代码。 改掉猜错的地方，复制，粘进 data/charts.js 的 CHARTS 数组。

手动做法：直接复制一段现成条目改。最少需要这几个字段：

{
  id: "my-chart",        // 必填，作品标识（一首歌一个，来自 info.txt 的 Path）
  level: "IN",           // 必填，难度名：AT / IN / HD / EZ / FM
  difficulty: "15.4",    // 难度数值，支持 "16+" 这种写法
  version: "v1.0",       // 版本号（给人看的）
  seq: 1,                // 排序号（机器看的，导入工具会自动算）
  title: "曲名",
  artist: "曲师",
  charterName: "霓虹组",   // 谱师名义：单个字符串，来自 info.txt 的 Charter:
  charters: ["小明", "小红"], // 实际谱师：**数组**，真正动手的人
  duration: 157,         // 时长，**单位秒**；页面显示时自动转 02:37
  bpm: [180],            // BPM，**数组**；变 BPM 就把所有值列进去
  editTime: 12304.25,    // 编辑净用时，单位秒
  desc: "简介。"
}

id 必须唯一且稳定，seq 必须能区分先后 —— 这两个决定了「哪些记录属于同一份谱」和「哪一版最新」。

版本是怎么算的

相同 id + 相同 level 的记录，会被认为是**同一份谱的不同版本**。 所以 aurora 的 IN 和 AT 是两条独立的版本线。

  • 首页每个组合只显示 seq 最大的那一版
  • 详情页默认显示最新版，并在下面列出完整的「版本历史」
  • 历史版本有独立链接：chart.html?id=aurora&lv=IN&v=1.0，可以单独下载
  • 排序为什么不用 version：版本号是自由文本，"v1.10" 按字符串比会比 "v1.9" 还小，会排错。所以另有一个自增的 seq

加新版本时，把新记录追加进数组即可，不要改动旧记录。 导入工具会自动读取已有版本并算出正确的 seq。

文件放哪

谱面文件放在 charts/<作品id>/<难度>-<版本>.pez， 例如 charts/aurora/IN-v1.0.pez。这样同一个作品的多个版本、多个难度 天然分居不同文件，不会互相覆盖。

改谱面信息时不要重传 .pez —— 调难度、写更新日志只改数据文件就够了。 谱面文件每次重传都会在 Git 历史里多留一份 20MB 的垃圾。

怎么改站点信息#

站点标题、署名、简介、页脚、侧边栏友情链接，全都在 data/charts.js 顶部的 window.SITE 里：

window.SITE = {
  title: "Phira 自制谱仓库",       // 顶栏和页脚显示的站名
  tagline: "个人自制谱面的归档与下载站",
  author: "Clarity",               // 显示成 by xxx
  intro: "第一行\n第二行",          // 首页那条简介，\n 会换行
  footer: "版权或免责声明",
  links: [                         // 侧边栏「链接」，不要就写 []
    { text: "Phira 官网", url: "https://phira.moe" }
  ]
};

没有找到 favicon.svg 想要的图标？它就是一个普通 SVG 文件，直接替换即可。

自己排版（Illustrator）#

整站的视觉都留了插槽。你可以用 Illustrator 出图后直接替换， 完全不用碰 JavaScript —— 只要把图放进 assets/design/， 再把路径填到配置里。

一、换图片

design: {
  logo: "assets/design/logo.svg",          // 顶栏图标，建议 48×48 透明底
  banner: "assets/design/banner.jpg",      // 首页顶部横幅，建议 1600×320
  background: "assets/design/bg.png",      // 全站底纹，建议做得很淡
  cardPlaceholder: "assets/design/na.svg", // 没有封面的作品用这张，建议 400×400
  accent: "#fb7299",                       // 强调色：按钮 / 选中态 / 链接一起变
  cardMinWidth: "190px",                   // 卡片最小宽度 → 一行放几张
  cardThumbRatio: "16 / 9"                 // 封面比例，方图填 "1 / 1"
}

上面每一项都可以留空，留空就用内置样式。
图片路径填错也不会把页面弄坏：Logo 会自动退回内置图标， 封面会自动换成按作品名生成的占位图，横幅加载失败则干脆不占位置。

二、调尺寸和形状

圆角、间距、字号、投影、栏宽这些都集中在 assets/css/wiki.css 最顶部那块「设计变量」里，改那一块就够了，不用往下翻具体规则。

变量管什么
--card-min卡片最小宽度，决定一排放几张
--card-thumb-ratio封面比例，1 / 1（方）或 16 / 9（横）
--card-gap卡片之间的间距
--card-radius卡片圆角
--card-shadow静止时的投影，写 none 就是纯扁平风
--card-shadow-hover鼠标悬停时的投影
--sidebar-width左侧导航宽度
--content-max整页最大宽度
--fz-base正文基准字号，想整体缩放就调它
--banner-height顶部横幅高度

三、换配色

只想换个主题色：把 design.accent 填成一个颜色就够了（比如 B 站粉 #fb7299），它会同时接管按钮、选中态和链接。

想细调：改 wiki.css 里颜色变量区块的 --link、 --bg-sub、--border、--text 等。 浅色和深色是两套，分别在 :root 和 html[data-theme="dark"] 里，改完记得两套都看一眼。

四、能整块替换的位置

HTML 里凡是带「插槽」字样的注释，都是留给你的替换区， 比如首页的顶部横幅和那条极简信息条。想彻底重做某一页的排版， 直接改对应 HTML 的结构即可 —— 数据仍然由 data/charts.js 提供， 渲染逻辑都在 assets/js/ 目录下（首页是 home.js、 详情页是 detail.js）。

小提示：Illustrator 导出卡片底图时， 建议导出成 PNG 或 SVG；如果要做成「卡片边框独立于封面」的那种设计， 改 .vc-thumb-wrap 的 background 与 padding 就能得到带边框的九宫格效果。

两种预览：短预览 / 完整视频#

预览拆成两个独立字段，别混：短预览才是内嵌播放的，完整视频只做成外链按钮。

字段长什么样页面上的效果
shortPreview
短预览		 { bvid: "BV1xx411c7mD",
  start: 42, note: "片段" }		 详情页里内嵌的播放器，点击后才加载（不拖慢页面）。
bvid 取自链接里 /video/BV1xx411c7mD 这一段；
start 可选，从第几秒开始播。
留空则不出现播放器，只提示去 B 站看。
bilibili
完整视频		 { bvid: "BV1xx411c7mD",
  note: "完整版" }		 只做一个外链按钮（新标签页打开），不占版面。
填了 bvid 就会自动拼出视频地址；也可以直接填 url。

两者可以填同一个 BV 号（最常见的情况就是同一个视频），也可以分开：短预览放一小段演示， 完整视频放全曲。导入工具里只填一个 BV 号时，两边会自动都用它。

内嵌播放器的兼容性由 B 站决定： 当页面以 file:// 直接打开、或视频作者关闭了外站播放时，播放器可能拒绝加载。 所以完整视频的外链按钮始终保留，作为兜底。

发布到 GitHub Pages#

这个站是纯静态的，不需要构建。最简单的做法：

  1. 新建仓库
    用你的新 GitHub 账号建一个仓库，建议命名 <用户名>.github.io，这样网址就是 https://<用户名>.github.io/，最干净。想用别的名字也可以， 访问路径会变成 https://<用户名>.github.io/仓库名/。
  2. 上传所有文件
    用 GitHub 网页的「Add file → Upload files」把 index.html、chart.html、import.html、 about.html、data/、assets/、 vendor/、charts/ 一起传上去。 注意保持文件夹层级，别把里面的文件拉平。
  3. 打开 Pages
    仓库 → Settings → Pages → Source 选 Deploy from a branch，分支选 main、 目录选 / (root)，保存。
  4. 等一两分钟
    回到 Pages 页面会看到绿色提示和网址，点进去就行了。

关于相对路径：本站全部使用相对路径，所以放在子目录下（比如 /仓库名/）也能正常工作，不需要改任何配置。

关于 .gitignore：如果以后用命令行推送， 注意别把 charts/ 里的谱面给忽略掉了。

关于大文件的注意事项#

你的谱面单个 5–20MB，未来可能到 30 份。有几个硬限制值得先知道：

限制数值影响
单个文件大小100 MB20MB 完全安全。
仓库建议体积1 GB30 份 × 20MB ≈ 600MB，接近但不超。再多就要考虑外部存储。
Pages 月流量约 100 GB（软限制）按 10MB 一份算，约一万次下载。个人站够用。
单次上传数量网页端约 100 个文件文件多时建议用 GitHub Desktop 或 git 命令行。

要提醒的一点：Git 会保存文件的每一个历史版本。 如果你之后更新了某份谱面，旧版本的 20MB 仍然留在仓库历史里， 体积会累积。所以谱面文件尽量「定稿后再传」， 不要频繁替换同一个文件。确实需要频繁更新时，可以另开一个仓库专门放谱面文件， 或者用 Cloudflare R2 / 对象存储这类外部方案，把下载链接指向外部地址 ——条目里的 file 字段支持填完整网址。

常见问题#

为什么下载 .pez 时浏览器提示有风险？
因为它不是浏览器认识的文件类型。它本质上就是个 zip 压缩包， 在 Phira 里才能打开。想彻底避免这个提示，可以把文件改名为 .pez.zip，但那会让 Phira 无法直接导入，不推荐。

中文显示成乱码方块？
页面统一使用 UTF-8，所有 HTML 都带了 <meta charset="utf-8">。 如果本地用某些编辑器打开 data/charts.js 修改后出现乱码， 记得把编辑器保存编码设成 UTF-8（无 BOM）。

想加一个「下载全部」按钮？
纯静态站没法一键打包多个文件（除非预先做好一个 zip）。 可以在 charts/ 下放一个打包好的 all-charts.zip， 然后在 data/charts.js 里加一条 links 指向它。

列表太长会不会卡？
不会。这个站是纯字符串渲染，没有引入任何前端框架， 一百份作品在手机上也是瞬间出来的。

改完 data/charts.js 页面没变？
浏览器缓存。用 Ctrl + F5 强制刷新一次。
